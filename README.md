# Random Guess

เว็บเกมทายตัวเลขที่ใช้คำใบ้และช่วงตัวเลขที่เหลือเพื่อค้นหาคำตอบ พัฒนาด้วย React และ TypeScript สำหรับนำเสนอใน Portfolio AiDEX โดยแสดงการแปลงกติกาเกมเป็นสถานะของแอป การออกแบบส่วนติดต่อผู้ใช้ และการทดสอบความถูกต้องอย่างเป็นระบบ

## แนวคิดและวัตถุประสงค์

ผู้เล่นเริ่มจากข้อมูลเพียงช่วงของตัวเลข แล้วใช้ผลการทายแต่ละครั้งเพื่อลดความเป็นไปได้ของคำตอบ โครงงานเน้นกติกาที่ตรวจสอบได้ ข้อมูลย้อนกลับที่เข้าใจง่าย และการใช้งานทั้งบนคอมพิวเตอร์และมือถือ

## ฟีเจอร์หลัก

- เลือกระดับความยากได้ 3 โหมด และสุ่มคำตอบเป็นจำนวนเต็มภายในช่วงที่เลือก
- แสดงเฉพาะช่วงตัวเลขที่ยังเป็นไปได้ พร้อมคำใบ้ “มากเกินไป” หรือ “น้อยเกินไป”
- แสดงจำนวนครั้งที่ใช้และโอกาสที่เหลือ
- แสดงประวัติการทายทั้งหมดตามลำดับ พร้อมสี ข้อความ และลูกศร เมื่อพื้นที่ไม่พอจะขึ้นบรรทัดใหม่
- ตรวจสอบข้อมูลก่อนนับโอกาส ป้องกันช่องว่าง ข้อมูลที่ไม่ใช่จำนวนเต็ม เลขนอกช่วงที่เหลือ และเลขซ้ำ
- ส่งคำตอบได้ด้วยปุ่ม Guess หรือ Enter ล้างช่องกรอกหลังทาย และคืน Focus หากเกมยังดำเนินอยู่
- แสดง Victory หรือ Game Over พร้อมคำตอบและจำนวนครั้งที่ใช้ และปิดรับคำตอบเมื่อเกมจบ
- มีปุ่มเริ่มใหม่ แอนิเมชันฉลอง และรองรับการตั้งค่าลดการเคลื่อนไหวของอุปกรณ์

## กติกาเกม

| ระดับ | ช่วงเริ่มต้น | จำนวนโอกาส | ระยะห่างที่เป็นสีเหลือง |
| --- | --- | --- | --- |
| Easy | 1–10 | 5 ครั้ง | ไม่เกิน 1 |
| Normal | 1–100 | 10 ครั้ง | ไม่เกิน 10 |
| Hard | 1–1000 | 15 ครั้ง | ไม่เกิน 100 |

เมื่อทายสูงกว่าคำตอบ ขอบบนจะเปลี่ยนเป็นเลขที่ทายลบ 1 เมื่อทายต่ำกว่าคำตอบ ขอบล่างจะเปลี่ยนเป็นเลขที่ทายบวก 1 เช่น คำตอบคือ 68 ในโหมด Normal: ทาย 80 จะเหลือ 1–79 และทาย 50 ต่อจะเหลือ 51–79

สีแดงหมายถึงห่างจากคำตอบเกินเกณฑ์ สีเหลืองหมายถึงอยู่ในเกณฑ์แต่ยังไม่ถูก และสีเขียวหมายถึงทายถูก เกณฑ์สีคงที่ตามช่วงเต็มของโหมด แม้ช่วงที่เหลือจะเล็กลง

การทายที่ผ่านกติกาใช้หนึ่งโอกาส ทายถูกจะชนะทันที รวมถึงการทายถูกในโอกาสสุดท้าย หากโอกาสหมดจะเป็น Game Over และเปิดเผยคำตอบ การเริ่มใหม่หรือเปลี่ยนโหมดจะสุ่มคำตอบและรีเซ็ตสถานะทั้งหมด โดยอาจสุ่มได้เลขเดิมตามธรรมชาติ

ช่องกรอกรับจำนวนเต็มฐานสิบ เช่น `68` ไม่รับรูปแบบ `1e2`, `0x10` หรือ `1.5` ข้อมูลที่ไม่ผ่านกติกาจะไม่เสียโอกาสและไม่เพิ่มประวัติ

## แนวทางออกแบบโค้ด

กติกาถูกแยกไว้ใน `src/game.ts` ซึ่งไม่ขึ้นกับ React และมีฟังก์ชันสำหรับสุ่มคำตอบ ตรวจข้อมูล ปรับช่วง จัดกลุ่มสี และตัดสินผล ส่วน UI รับผลลัพธ์ไปแสดงและจัดการช่องกรอกกับ Focus

การตรวจข้อมูลเกิดก่อนเปลี่ยนสถานะเกม ประวัติการทายเป็นข้อมูลอ้างอิงในการนับโอกาส และการตัดสินว่าทายถูกเกิดก่อนตรวจว่าโอกาสหมด เพื่อลดความคลาดเคลื่อนระหว่างข้อมูลบนหน้าจอกับกติกา

## โครงสร้างโปรเจกต์

```text
public/
  favicon.svg                 ไอคอนเกม
src/
  game.ts                     กติกาและสถานะเกม
  App.tsx                     หน้าจอและการส่งคำตอบ
  components/
    GuessHistory.tsx          ประวัติการทายและคำอธิบายสี
    Celebration.tsx           แอนิเมชันฉลอง
  main.tsx                    จุดเริ่มต้น React
  styles.css                  ธีมและการจัดวางหลายขนาดหน้าจอ
tests/
  game.test.ts                ทดสอบกติกาเกม
  App.test.tsx                ทดสอบการโต้ตอบกับหน้าจอ
  setup.ts                    ตั้งค่าการทดสอบ
index.html                    ชื่อและข้อมูลเว็บไซต์
vite.config.ts                ตั้งค่า Vite และ Vitest
tsconfig.json                 ตั้งค่า TypeScript
package.json                  Dependencies และคำสั่ง
package-lock.json             ล็อกเวอร์ชัน Dependencies
```

## วิธีเปิดเกมในเครื่อง

ใช้ Node.js 22 ตั้งแต่ 22.12.0 หรือ Node.js 24 ขึ้นไป และ npm เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วรัน:

```sh
npm ci
npm run dev
```

เปิด URL ที่ Terminal แสดง โดยปกติคือ `http://127.0.0.1:5173/` หยุดเซิร์ฟเวอร์ด้วย `Ctrl+C` บน Windows สามารถใช้ `npm.cmd` แทน `npm` หาก PowerShell ไม่อนุญาตให้เรียกสคริปต์ npm

## การทดสอบและสร้างไฟล์พร้อมใช้งาน

```sh
npm audit
npm test
npm run typecheck
npm run build
```

คำสั่ง Build สร้างไฟล์ใน `dist/` เปิดตรวจไฟล์ที่สร้างแล้วได้ด้วย `npm run preview` จากนั้นเปิด URL ที่ Terminal แสดง โดยปกติคือ `http://127.0.0.1:4173/`

ผลตรวจสำเนาสำหรับ Portfolio วันที่ 4 พฤศจิกายน 2569 ด้วย Node.js 24.22.0 และ npm 11.19.1:

| รายการ | ผล |
| --- | --- |
| npm audit | ไม่พบช่องโหว่ที่มีรายงานใน Dependency Tree ณ เวลาตรวจ |
| Automated Tests | ผ่าน 44 Tests จาก 2 ไฟล์ |
| Typecheck | ผ่าน |
| Production Build | ผ่าน |

Tests ครอบคลุมขอบเขตการสุ่มทุกโหมด จำนวนโอกาส การปรับช่วงโดยไม่ตัดคำตอบ สีและ Threshold ประวัติ Validation เลขซ้ำ การล้าง Input การคืน Focus การส่งด้วยปุ่มและ Enter การกดซ้ำ ชนะ แพ้ เริ่มใหม่ และเปลี่ยนโหมด

Tests ของ UI ใช้ jsdom จึงไม่ทดแทนการตรวจภาพและแอนิเมชันใน Browser จริง ผู้พัฒนาได้ทดลอง Gameplay และยืนยัน Victory, Game Over, Auto-Clear Input, Invalid Input ที่ไม่หักโอกาส, Easy, Normal และ Restart แล้ว

## บทบาทผู้พัฒนาและการใช้ AI

ผู้พัฒนากำหนดแนวคิด ขอบเขต และข้อกำหนด Gameplay เลือกแนวทางการใช้งาน ตรวจรับงาน และทดลองเล่นจริงเพื่อยืนยันพฤติกรรมของเกม

กระบวนการพัฒนาใช้ ChatGPT/Codex ช่วยสร้างและทบทวนโค้ด UI, Game Logic, Tests และเอกสาร รวมถึงช่วยตรวจ Dependencies และผลการทดสอบ การนำเสนอโครงงานจึงระบุการใช้ AI เป็นผู้ช่วยพัฒนาตามจริง

ประเด็นทางเทคนิคที่โครงงานแสดง ได้แก่ การจัดการ State การตรวจสอบข้อมูลก่อนเปลี่ยน State การแยก Logic ออกจาก UI การออกแบบข้อมูลย้อนกลับ และการตรวจพฤติกรรมด้วย Automated Tests

## การเข้าถึงและข้อจำกัด

- รองรับการใช้แป้นพิมพ์ มี Label และข้อความแจ้งผลสำหรับโปรแกรมอ่านหน้าจอ รวมถึงใช้ข้อความกับลูกศรประกอบสี
- จัดวางหน้าจอด้วย Responsive CSS และปิดแอนิเมชันเมื่อเลือก `prefers-reduced-motion`
- สถานะเกมเก็บในหน่วยความจำเบราว์เซอร์ การรีเฟรชหน้าจะเริ่มรอบใหม่
- ฟอนต์จาก Google Fonts ต้องใช้อินเทอร์เน็ต หากโหลดไม่ได้จะใช้ฟอนต์สำรองในเครื่อง
- เก็บ Source, Assets, Tests, Configuration และ `package-lock.json` ใน Repository ส่วน `node_modules/`, `dist/`, ไฟล์รายงานการทดสอบ และไฟล์ Environment ที่มีค่าลับถูกกำหนดไว้ใน `.gitignore`
